### Phase 6C: Nginx Reverse Proxy Configuration

Configure Nginx as a reverse proxy for the deployed services. This phase runs after the deployment pipeline (Phase 6A or 6B) and before verification (Phase 7). It is **optional** — skipped if the user chose "Skip Nginx" in Phase 4.

> **Entry condition**: This phase runs only when ALL of the following are true:
> - User selected Nginx configuration in Phase 4
> - Nginx is installed on the server (detected in pre-flight)
> - `NGINX_DOMAIN` is set (user provided a domain name)

#### Step 1: SSL Certificate Detection

Detect existing SSL certificates on the server. Execute via `ssh_exec`:

```bash
DOMAIN="{{NGINX_DOMAIN}}"
# Extract primary domain (first one if space-separated list)
PRIMARY_DOMAIN=$(echo "$DOMAIN" | awk '{print $1}')

SSL_CERT=""
SSL_KEY=""
SSL_EXTRA=""
HAS_SSL=false

# 1. Check Let's Encrypt
LE_CERT="/etc/letsencrypt/live/${PRIMARY_DOMAIN}/fullchain.pem"
LE_KEY="/etc/letsencrypt/live/${PRIMARY_DOMAIN}/privkey.pem"
if [ -f "$LE_CERT" ] && [ -f "$LE_KEY" ]; then
    SSL_CERT="$LE_CERT"
    SSL_KEY="$LE_KEY"
    HAS_SSL=true
    # Check for Let's Encrypt options and dhparams
    LE_OPTIONS="/etc/letsencrypt/options-ssl-nginx.conf"
    LE_DHPARAMS="/etc/letsencrypt/ssl-dhparams.pem"
    if [ -f "$LE_OPTIONS" ] && [ -f "$LE_DHPARAMS" ]; then
        SSL_EXTRA="    include ${LE_OPTIONS};\n    ssl_dhparam ${LE_DHPARAMS};"
    fi
    echo "SSL: Let's Encrypt certificates found"
fi

# 2. Check existing Nginx configs for ssl_certificate
if [ "$HAS_SSL" = "false" ]; then
    EXISTING_CERT=$(grep -rh 'ssl_certificate ' /etc/nginx/sites-enabled/ 2>/dev/null | head -1 | awk '{print $2}' | tr -d ';')
    EXISTING_KEY=$(grep -rh 'ssl_certificate_key ' /etc/nginx/sites-enabled/ 2>/dev/null | head -1 | awk '{print $2}' | tr -d ';')
    if [ -n "$EXISTING_CERT" ] && [ -f "$EXISTING_CERT" ] && [ -n "$EXISTING_KEY" ] && [ -f "$EXISTING_KEY" ]; then
        SSL_CERT="$EXISTING_CERT"
        SSL_KEY="$EXISTING_KEY"
        HAS_SSL=true
        echo "SSL: Using certificates from existing Nginx config"
    fi
fi

# 3. Check common locations
if [ "$HAS_SSL" = "false" ]; then
    for dir in /etc/ssl/certs /etc/nginx/ssl /etc/pki/tls/certs; do
        for cert_file in "$dir"/"${PRIMARY_DOMAIN}"*.pem "$dir"/"${PRIMARY_DOMAIN}"*.crt; do
            if [ -f "$cert_file" ]; then
                SSL_CERT="$cert_file"
                # Try to find matching key
                key_file=$(echo "$cert_file" | sed 's/\.pem$/.key/; s/\.crt$/.key/')
                [ -f "$key_file" ] && SSL_KEY="$key_file"
                # Also check in private subdirectory
                key_dir=$(dirname "$cert_file" | sed 's/certs/private/')
                [ -f "$key_dir/$(basename "$key_file")" ] && SSL_KEY="$key_dir/$(basename "$key_file")"
                if [ -n "$SSL_KEY" ] && [ -f "$SSL_KEY" ]; then
                    HAS_SSL=true
                    echo "SSL: Certificates found in $dir"
                fi
                break 2
            fi
        done
    done
fi

if [ "$HAS_SSL" = "false" ]; then
    echo "SSL: No certificates found — will use HTTP-only template"
fi

echo "HAS_SSL=$HAS_SSL"
echo "SSL_CERT=$SSL_CERT"
echo "SSL_KEY=$SSL_KEY"
echo "SSL_EXTRA=$SSL_EXTRA"
```

Record `HAS_SSL`, `SSL_CERT`, `SSL_KEY`, `SSL_EXTRA` for template rendering.

If the user explicitly chose "HTTP only" or "I'll set up SSL later" in Phase 4, skip SSL detection and set `HAS_SSL=false`.

#### Step 2: Check for Version Marker (Idempotent Config)

Check if an Nginx config already exists for this project with a version marker. If it does, the config was previously generated by this skill — skip reconfiguration unless the user explicitly requested it.

```bash
NGINX_SITE_FILE="/etc/nginx/sites-available/{{NGINX_SITE_NAME}}"
if [ -f "$NGINX_SITE_FILE" ]; then
    if grep -q "# {{PROJECT_NAME}} nginx config v" "$NGINX_SITE_FILE"; then
        EXISTING_VERSION=$(grep "# {{PROJECT_NAME}} nginx config v" "$NGINX_SITE_FILE" | grep -oP 'v\d+')
        echo "EXISTING_NGINX_CONFIG=true"
        echo "EXISTING_VERSION=$EXISTING_VERSION"
    else
        echo "EXISTING_NGINX_CONFIG=true"
        echo "EXISTING_VERSION=unknown"
    fi
else
    echo "EXISTING_NGINX_CONFIG=false"
fi
```

If `EXISTING_NGINX_CONFIG=true` and we are NOT in force mode:

```
AskUserQuestion:
  question: "An existing Nginx config for {{PROJECT_NAME}} was found ({{EXISTING_VERSION}}). What would you like to do?"
  candidates:
    - "Keep existing config (skip Nginx reconfiguration)"
    - "Overwrite with new config"
    - "Show me the existing config first"
```

If "Keep existing", skip the rest of this phase. If "Show me", execute `cat "$NGINX_SITE_FILE"` and re-ask. If "Overwrite", continue.

In auto mode: keep existing config if version marker matches, overwrite otherwise.

#### Step 3: Backup Existing Nginx Config

If an existing config will be overwritten, create a timestamped backup:

```bash
if [ -f "$NGINX_SITE_FILE" ]; then
    cp "$NGINX_SITE_FILE" "${NGINX_SITE_FILE}.bak.$(date +%Y%m%d_%H%M%S)"
    echo "Existing Nginx config backed up"
fi
```

#### Step 4: Select and Render Nginx Template

Choose the template based on SSL detection:

| SSL Detected | Template | Result |
|---|---|---|
| yes | `site-https.tpl` | HTTPS with HTTP→HTTPS redirect |
| no | `site-http.tpl` | HTTP only with warning comment |

The template has already been rendered in Phase 5 (Template Rendering). At this point the rendered file is in `ops/templates/` on the server. If not (e.g., Nginx was configured during Phase 4 after templates were already rendered), render it now:

Replace these variables in the selected template:
- `{{PROJECT_NAME}}` → project name
- `{{NGINX_DOMAIN}}` → domain name(s), space-separated for multi-domain
- `{{BACKEND_PORT}}` → backend service port
- `{{FRONTEND_PORT}}` → frontend service port
- `{{NGINX_SSL_CERT}}` → SSL certificate path
- `{{NGINX_SSL_KEY}}` → SSL key path
- `{{NGINX_SSL_EXTRA}}` → additional SSL directives (Let's Encrypt options)

**Conditional blocks in the template:**
- `{{IF HAS_BACKEND}}...{{ENDIF HAS_BACKEND}}` — include `/api/` and `/health` location blocks only for fullstack projects
- For `backend_only` projects: proxy root `/` to the backend port, remove frontend upstream
- For `monolith` projects: proxy root `/` to the single service port, no separate `/api/` block

#### Step 5: Install Nginx Config

Write the rendered config to `/etc/nginx/sites-available/` and create the symlink in `/etc/nginx/sites-enabled/`:

```bash
NGINX_SITE_NAME="{{NGINX_SITE_NAME}}"
RENDERED_CONFIG="{{PROJECT_DIR}}/ops/templates/nginx-site.conf"

# Write config
sudo cp "$RENDERED_CONFIG" "/etc/nginx/sites-available/$NGINX_SITE_NAME"

# Create symlink (remove old one first)
sudo rm -f "/etc/nginx/sites-enabled/$NGINX_SITE_NAME"
sudo ln -s "/etc/nginx/sites-available/$NGINX_SITE_NAME" "/etc/nginx/sites-enabled/$NGINX_SITE_NAME"

echo "Nginx config installed: /etc/nginx/sites-available/$NGINX_SITE_NAME"
```

#### Step 6: Clean Duplicate Domain Blocks

Check if the domain is also configured in the default Nginx site (common issue when deploying to a server that already has a catch-all config):

```bash
DEFAULT_SITE="/etc/nginx/sites-enabled/default"
if [ -f "$DEFAULT_SITE" ]; then
    PRIMARY_DOMAIN=$(echo "{{NGINX_DOMAIN}}" | awk '{print $1}')
    if grep -q "server_name.*${PRIMARY_DOMAIN}" "$DEFAULT_SITE" 2>/dev/null; then
        echo "WARNING: Domain ${PRIMARY_DOMAIN} also appears in default Nginx config"
        echo "This may cause routing conflicts. Consider removing it from the default site."
    fi
fi
```

Also clean up stale `.bak` files from sites-enabled (these shouldn't be there — only symlinks belong in sites-enabled):

```bash
sudo find /etc/nginx/sites-enabled/ -name "*.bak*" -delete 2>/dev/null || true
```

#### Step 7: Test Nginx Configuration

```bash
sudo nginx -t 2>&1
```

If `nginx -t` fails:

```bash
# Capture the error
NGINX_ERROR=$(sudo nginx -t 2>&1)
echo "Nginx config test FAILED:"
echo "$NGINX_ERROR"

# Restore backup
if [ -f "${NGINX_SITE_FILE}.bak."* ]; then
    LATEST_BACKUP=$(ls -t "${NGINX_SITE_FILE}.bak."* 2>/dev/null | head -1)
    sudo cp "$LATEST_BACKUP" "$NGINX_SITE_FILE"
    sudo nginx -t 2>&1 && echo "Backup config restored successfully" || echo "WARNING: Backup config also failed!"
fi
```

Report the error to the user:

```
AskUserQuestion:
  question: "Nginx config test failed:\n{{NGINX_ERROR}}\n\nWhat would you like to do?"
  candidates:
    - "Show me the generated config — I'll fix it manually"
    - "Skip Nginx configuration for now"
    - "Retry with HTTP-only template (skip SSL)"
```

#### Step 8: Reload Nginx

If `nginx -t` passes, reload Nginx:

```bash
sudo systemctl reload nginx
echo "Nginx reloaded successfully"
```

Verify Nginx is serving the domain:

```bash
# Quick verification — try to reach the domain via localhost (in case DNS hasn't propagated)
{{IF HAS_SSL}}
curl -sf --max-time 5 -k "https://localhost/" -H "Host: {{PRIMARY_DOMAIN}}" > /dev/null 2>&1 \
    && echo "HTTPS: responding" \
    || echo "HTTPS: not responding via localhost (may need DNS)"
{{ENDIF HAS_SSL}}

curl -sf --max-time 5 "http://localhost/" -H "Host: {{PRIMARY_DOMAIN}}" > /dev/null 2>&1 \
    && echo "HTTP: responding" \
    || echo "HTTP: not responding via localhost (may need DNS)"
```

#### Step 9: API Proxy Location Block (Conditional)

For fullstack projects with a separate backend, the Nginx config includes an `/api/` location block that proxies requests directly to the backend. This is configured in the template with the `{{IF HAS_BACKEND}}` conditional block.

The template also includes a `/health` location that proxies to the backend health endpoint — used by external monitoring tools.

**Important SSE/WebSocket settings included in all proxy blocks:**

```nginx
proxy_buffering off;              # Critical for SSE streaming
proxy_read_timeout 3600s;         # 1-hour timeout for long connections
proxy_send_timeout 3600s;
proxy_connect_timeout 60s;
chunked_transfer_encoding on;
proxy_set_header Connection "upgrade";  # WebSocket upgrade
proxy_set_header Upgrade $http_upgrade;
```

These settings are essential for AI agent streaming (SSE), real-time features (WebSocket), and long-polling endpoints.

#### Step 10: Multi-Domain Support

The `NGINX_DOMAIN` variable supports space-separated domains:

```
NGINX_DOMAIN="example.com www.example.com api.example.com"
```

This maps directly to Nginx's `server_name` directive which natively handles multiple domains:

```nginx
server_name example.com www.example.com api.example.com;
```

**SSL consideration for multi-domain:** SSL certificates must cover all listed domains. For Let's Encrypt, use a SAN (Subject Alternative Name) certificate or wildcard certificate. The skill detects certificates for the primary domain only — the user is responsible for ensuring the certificate covers all domains.

---

**Phase 6C output gate:** Nginx must be running (`systemctl is-active nginx` returns "active") and `nginx -t` must pass. The domain should be accessible via HTTP (and HTTPS if SSL was configured). If DNS hasn't propagated, localhost-based verification via Host header is acceptable.
