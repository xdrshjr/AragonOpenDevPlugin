# Spec 08: Ops Toolkit Generation

## Purpose

Generate a complete, independent set of ops scripts that work both locally and on the server, allowing users to manage deployed services without the SKILL.

## Design Principles

1. **Independence**: Scripts work without Claude Code or the SKILL
2. **Self-contained**: Each script includes its own error handling and help text
3. **Consistent style**: All scripts follow the same color/logging/argument conventions
4. **Idempotent**: Running any script multiple times produces the same result
5. **Parameterized**: All project-specific values come from `config.env`

## Generated Ops Directory Structure

```
ops/
├── config.env                  # All configurable parameters
├── deploy.sh                   # One-command build + deploy (new, not in original)
├── install.sh                  # systemd service registration
├── install-deps.sh             # Dependency installation
├── uninstall.sh                # Service removal
├── status.sh                   # Service status display
├── logs.sh                     # Log viewer
├── healthcheck.sh              # Watchdog health check
├── README.md                   # Usage documentation (generated)
└── templates/
    ├── {{PROJECT_NAME}}-backend.service
    ├── {{PROJECT_NAME}}-frontend.service
    ├── {{PROJECT_NAME}}-watchdog.service
    ├── {{PROJECT_NAME}}-watchdog.timer
    ├── {{PROJECT_NAME}}-logrotate
    ├── {{PROJECT_NAME}}-nginx        # (if Nginx configured)
    └── {{PROJECT_NAME}}-nginx-http   # (if Nginx configured)
```

For Docker mode, additional scripts:
```
ops/
├── docker-deploy.sh            # Docker build + up
├── docker-status.sh            # Container status
├── docker-logs.sh              # Container logs
└── docker-stop.sh              # Container stop
```

## Naming Convention

All generated files use `{{PROJECT_NAME}}` as the prefix:

| Current (InkClaw) | Generalized |
|-------------------|-------------|
| `inkclaw-backend.service` | `{{PROJECT_NAME}}-backend.service` |
| `inkclaw-frontend.service` | `{{PROJECT_NAME}}-frontend.service` |
| `inkclaw-watchdog.service` | `{{PROJECT_NAME}}-watchdog.service` |
| `inkclaw` (nginx site) | `{{PROJECT_NAME}}` or `{{NGINX_SITE_NAME}}` |

The `PROJECT_NAME` is:
1. Auto-inferred from `package.json`.name or directory name
2. Converted to kebab-case
3. Confirmed by user during project analysis phase

## config.env Template

```bash
# =============================================================================
# {{PROJECT_NAME}} Service Configuration
# Read by install.sh — re-run install.sh after modifying this file.
# Generated by web-deployer skill on {{DEPLOY_TIMESTAMP}}
# =============================================================================

# Project
PROJECT_NAME={{PROJECT_NAME}}

# Node.js binary path (auto-detected if empty)
# NODE_BIN=/path/to/node

# Ports
{{IF BACKEND_DETECTED}}
BACKEND_PORT={{BACKEND_PORT}}
{{ENDIF BACKEND_DETECTED}}
{{IF FRONTEND_DETECTED}}
FRONTEND_PORT={{FRONTEND_PORT}}
{{ENDIF FRONTEND_DETECTED}}

# Watchdog
WATCHDOG_INTERVAL={{WATCHDOG_INTERVAL}}
WATCHDOG_FAIL_THRESHOLD={{WATCHDOG_FAIL_THRESHOLD}}
WATCHDOG_STATE_DIR=/tmp

# Nginx reverse proxy (leave NGINX_DOMAIN empty to skip)
NGINX_DOMAIN="{{NGINX_DOMAIN}}"
NGINX_SITE_NAME="{{NGINX_SITE_NAME}}"

# Logging
LOG_DIR=logs
LOG_MAX_SIZE={{LOG_MAX_SIZE}}
LOG_ROTATE_COUNT={{LOG_ROTATE_COUNT}}

# Health check endpoints
{{IF BACKEND_DETECTED}}
BACKEND_HEALTH_URL="http://localhost:${BACKEND_PORT}/health"
{{ENDIF BACKEND_DETECTED}}
{{IF FRONTEND_DETECTED}}
FRONTEND_HEALTH_URL="http://localhost:${FRONTEND_PORT}/"
{{ENDIF FRONTEND_DETECTED}}
```

## deploy.sh — New One-Command Script

This is a new script not in the original InkClaw ops:

```bash
#!/usr/bin/env bash
# One-command deploy: pull latest code, install deps, build, restart services
# Usage: ./ops/deploy.sh [--skip-build] [--skip-deps]

# Steps:
# 1. git pull (if git repo)
# 2. Install dependencies (unless --skip-deps)
# 3. Build project (unless --skip-build)
# 4. Run install.sh to update systemd units
# 5. Verify services are healthy
```

This gives users a single command for redeployment after initial setup.

## Script Generalization Changes

### From InkClaw-specific to Generic

| Hardcoded in InkClaw | Generalized |
|---------------------|-------------|
| `if [[ ! -f "$PROJECT_DIR/backend/app.py" ]]` | Dynamic backend detection from config |
| `inkclaw-backend.service` | `${PROJECT_NAME}-backend.service` |
| `VENV_PYTHON="$PROJECT_DIR/backend/.venv/bin/python"` | `VENV_PYTHON` from config.env or auto-detected |
| `if [[ ! -d "$PROJECT_DIR/out" ]]` | Build output dir from config |
| Flask-specific `ExecStart` | Framework-agnostic `ExecStart` from config |

### Key Abstractions

1. **Service list**: Instead of hardcoding "backend" and "frontend", read service definitions from config
2. **Health endpoints**: Configurable per-service health URLs in config.env
3. **Build commands**: Project-specific build commands in config
4. **Entry points**: Per-service start commands in config

## Placement Strategy

### Local (user's machine)

```
project-root/
└── ops/                        # Generated ops toolkit
    ├── config.env
    ├── deploy.sh
    └── ...
```

### Server

```
/home/deploy/project-name/
└── ops/                        # Same ops toolkit, uploaded via SFTP
    ├── config.env              # Server-specific values
    ├── deploy.sh
    └── ...
```

The server copy may have different `config.env` values (e.g., different paths).

## README.md Generation

Auto-generate an `ops/README.md` documenting:
- Quick start instructions
- All available scripts with usage examples
- Configuration reference (all config.env variables)
- Troubleshooting guide
- Architecture overview (systemd units, watchdog, logrotate)

Language follows user's choice (Chinese or English).

## Gitignore Recommendations

After generating ops scripts, check if `.gitignore` exists and suggest adding:
```
.deploy-backups/
ops/config.env  # Contains server-specific values
```

But NOT ignoring the ops scripts themselves — they should be committed.
